# Mode: new

Build a new local surface at the requested fidelity. An external website may already
determine its design. DESIGN.md is optional for a one-off mockup.

Read `references/intake.md` and `references/verification.md`. For existing-site input,
also read `references/source-fidelity.md`. With direction open, read
`references/directions.md`. Load other topics only as relevant to the work.

## 1. Establish intent

Determine audience, task, scope, content, output format and fidelity. Infer from the
request and source first; ask only for material gaps. For recreation, inspect the source.
For an open aesthetic, show a visual shortlist for either register; honor an explicit
choice or permission to choose autonomously.

## 2. Make the design concrete

Write a compact brief: source role, direction and example IDs, defining visual properties,
content, region proportions, applicable states and verification targets. An ASCII sketch
is optional. Reuse established tokens; record reusable decisions in existing DESIGN.md
or create one when useful for an ongoing system. A mockup needs no system interview.

## 3. Build and inspect early

Build the main viewport with actual fonts, assets and content. Render and inspect its
composition and type before completing other regions. For product UI, apply
`references/craft.md` after composition is right: nested radii, optical alignment,
depth, icon weight, press feedback and the frequency budget for motion. Extend the chosen vocabulary
through the requested surface and responsive layouts. Implement states relevant to the
agreed fidelity. For image output use the available image workflow; for HTML or a
prototype use the project's stack or a simple implementation suited to the request.
Do not silently substitute an image for working UI or vice versa.

## 4. Verify and correct

Follow `references/verification.md`: compare with the source or chosen examples, inspect
requested widths, exercise the main task and relevant states, and run appropriate project
checks. Correct the largest observed mismatches and re-render affected output.

## 5. Deliver

Provide the artifact, key choices, source or gallery references, verification evidence,
asset substitutions and unresolved limitations. Update reusable documentation when
applicable. Screenshots alone do not prove interactive accessibility.
