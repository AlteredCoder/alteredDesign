# Mode: styles

Help a user see and choose a direction. Do not edit the target project, create DESIGN.md,
or start implementation from a styles-only request.

Read `references/directions.md`. Prefer the app reference pack for dashboards and
workspaces; use the general pack for sites. Build the illustrated board with
`scripts/board.py`, and inspect selected images before presenting them.

1. Named direction: show its two images and the distinguishing features. All styles:
   show the overview and link to the complete gallery.
2. Open choice: show a browsable overview with relevant directions and two or three
   images per direction. A small shortlist can help a focused request; never present
   its size as a capability limit. When users ask for more, expand the board. Record
   project-specific translations, tradeoffs and retained interactions using its context
   input. Custom references, combinations and preserving an existing look remain valid.
3. Show actual images and source links through available image presentation tools or
   Markdown embedding. If inline display is unsupported, link to the local gallery and
   source pages and state the limitation. A URL list does not count as displayed images.
4. After selection, summarize properties to carry forward and resume an already requested
   build. A styles-only request ends with the reference presentation.

The examples are a curated snapshot. Fresh search results need visual inspection and
source verification; the year of a trend article does not date each design example.
