# Mode: add

Extend an existing UI in its own design language. Read `references/intake.md` and
`references/verification.md`, then topic references only for new behavior or unresolved
visual decisions. DESIGN.md is optional when source components already establish the system.

1. Inspect the nearest existing screen, its rendered appearance, components, tokens,
   navigation and relevant states. Reuse exact established values and behavior.
2. Infer the task, placement, data and flow from the request and code. Ask only about
   material gaps. Do not offer a new direction unless the user requests one.
3. Write a compact brief identifying the neighbor, reused components, new content,
   applicable states and verification targets. Keep common navigation and controls
   predictable; do not force unrelated page content to identical coordinates.
4. Build the surface at the requested fidelity using existing components where suitable.
   New components follow the established roles and relevant state conventions; apply
   `references/craft.md` to new controls and surfaces.
5. Render at the relevant widths and compare shared UI with the neighbor. Exercise the
   task and applicable states. Correct observed defects and run appropriate project checks.
6. Deliver files, reused and added elements, verification evidence and limitations.
   Record reusable additions in existing DESIGN.md when applicable.
